## 一、 规则分类体系

本仓库所有规则按应用场景统一划分为五大一级目录：

| 分类目录 | 覆盖领域 | 典型场景 |
| :--- | :--- | :--- |
| `rules/video/` | 影视与流媒体娱乐 | B站、影视直链嗅探、弹幕双擎直连 |
| `rules/audio/` | 有声书与高品质音乐 | 声阅有声小说、小酷音乐、评书相声 |
| `rules/comic/` | 漫画与网络文学 | 多画质漫画阅读、轻小说连载 |
| `rules/crawler/` | 网页与平台数据采集 | FlowEngine DAG 采集规格书、Scrapling 适配器 |
| `rules/tool/` | 实用扩展与辅助工具 | 弹幕网关镜像、解析插件、数据转换 |

## 二、 规则目录与命名规范

每条规则采用 **`分类/英文名-作者名/`** 作为唯一命名空间（Slug），彻底避免重名覆盖：

```text
rules/
└── audio/
    └── syapp-zhao/
        ├── rule.json       # 规则核心定义 (JSON 格式，包含 title, author, version 等)
        └── meta.json       # 规则元数据 (中文展示名、更新日志 Changelog、介绍等)
```

### 1. `rule.json` (核心规则文件)
必须包含有效的 JSON 格式及以下基本属性：
- `title`: 规则标题 (如 `"声阅APP"`)
- `author`: 规则作者 (如 `"zhao"`)
- `version`: 语义化版本号 (如 `"1.0.8"`)
- `col_type`: 布局形态 (如 `"movie_3"`, `"audio"`)
- `find_rule`: 页面解析脚本 (支持 `js:` 前缀)

### 2. `meta.json` (元数据与更新日志)
```json
{
  "name": "声阅APP",
  "category": "audio",
  "author": "zhao",
  "version": "1.0.8",
  "description": "海量有声小说与听书聚合，支持连续章节自动无缝播放与多维章节自动定位",
  "updatedAt": "2026-11-05",
  "changelog": [
    "1.0.8: 修复二级详情页下拉分页触底加载问题与音频连播队列历史快照",
    "1.0.0: 初始版本发布"
  ]
}
```

## 三、 贡献与提 PR 流程

### 方式 1：DeepCloud 客户端零门槛一键投递（推荐，无需账号）
1. 打开 DeepCloud 客户端 ➔ 进入 **「插件中心」**；
2. 点击右上角 **【投递规则 (提 PR)】**；
3. 粘贴海阔云剪切板口令（`￥home_rule_url￥...`）或 JSON 文本，系统将**在本地自动脱壳并识别出规则信息**；
4. 填写简要更新说明，点击 **【一键提交审核】** 即可！
*(由官方 Bot 自动代提 PR，无需登录 GitHub 账号，耗时仅需 3 秒)*

### 方式 2：GitHub 开发者标准 PR 流程
1. **Fork 本仓库** 到您的个人 GitHub 空间；
2. 新建分支：`git checkout -b feat/add-my-rule`；
3. 按照规范在 `rules/{category}/{slug}/` 下添加或更新文件；
4. 运行本地验证：`npm run validate`；
5. 提交并向 `main` 分支发起 Pull Request。

## 四、 自动化机审与安全防范 (GitHub Actions)

为了保障全网用户的网络与数据安全，每个 Pull Request 提交后，GitHub Actions 将在 5 秒内全自动运行以下测试：

1. **语法与结构合规性**：自动检验 `rule.json` 是否为规范可解析的合法 JSON；
2. **主动恶意特征扫描**：
   - 严禁探测本地回环网络与局域网 IP（`127.0.0.1`、`localhost`、`192.168.*`、`10.*`）；
   - 严禁调用危险系统进程执行命令；
3. **自动化测试回贴**：体检通过后，机器人自动在 PR 下方打上 ✅ 绿标并留言体检报告，管理员确认后即可一键 Merge！

## 五、 版本管理与冲突解决机制

1. **版本升级**：
   - 针对已有规则的修复或更新，直接修改对应目录下的 `rule.json` 并递增 `version`（例如 `1.0.8 -> 1.0.9`）；
   - Git commit 历史将永久保存每一次改动，任何破坏性更新均可秒级无损一键回滚 (`Revert`)；
2. **同名规则竞争**：
   - 不同作者编写了相同站点的规则时，以不同的作者后缀隔离（如 `syapp-zhao` 与 `syapp-mowen`）；
   - 插件中心将根据版本号与更新频率同时展示，由用户自由选择装载，激发社区良性创新。
